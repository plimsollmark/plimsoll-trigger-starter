Can someone quietly change the answer?
A returns report may be used to approve refunds or investigate a product defect. A plain log can be edited. Plimsoll checks a result against its execution record; its separate signing harness can preserve those records as a signed ledger for later review.
Three different checks
Checksum: a fingerprint of the request or result. Like comparing a parcel with its packing slip, it catches disagreement between the returned bytes and the recorded fingerprint.
Signature: the harness signs its checked record. Like a seal made with a controlled stamp, it lets a reviewer detect changes without possessing the signing key.
Expected request list: the caller's separate list of work it sent. Like matching receipts to purchase orders, it catches an older, valid ledger that leaves later work out.
The two recorded calculations
  1. Count returns by product.
  2. Compare return rates.
Each is a real, independent JavaScript run on local Docker under gVisor, a sandbox runtime providing the reported kernel isolation tier. The signing harness checks and signs each record, then links the ledger entries.
This proves integrity relative to the trusted harness key and expected list. It does not prove the program's conclusion is correct, or that the host was uncompromised. Keep the trusted key and expected list separately from a bundle received from someone else.

Verify the evidence yourself
Install the public plimsoll-attest command following the example README. Download the original ledger, public key, and expected request list into one directory.
plimsoll-attest verify -pub harness.pub -expect expected.txt bundle.jsonl
The original passes. Substitute changed-output.jsonl, missing-run.jsonl, or earlier-valid-bundle.jsonl to reproduce a rejection. The earlier bundle passes without -expect, which is why the independently retained expected list matters.
